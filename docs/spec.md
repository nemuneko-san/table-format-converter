# Table Format Converter 仕様

さまざまな表記法の表を専用タブの入力欄に貼り付けると、選んだ出力形式へ相互変換して表示・コピーできる Chrome 拡張。

- 仕様の一次情報: 質問書 Round 1 の回答ダイジェスト（2026-11-12 提出、回答済 48 問 / 未回答 1 問 / 非表示スキップ 4 問）
- 「その他」「おまかせ」回答と非表示質問の解釈: 司令塔判断（本書「司令塔判断」節）
- 回答の空白を実装時に埋めた箇所: 本書「実装者判断」節

### 回答どうしの関係で補った点

- **Q4**: ツールバーアイコンのクリックで専用タブを開く（`default_popup` を置かず、service worker の `chrome.action.onClicked` で開く）。すでに開いているタブがあればそれをアクティブにする。
- **Q47**: 直近の入力は `chrome.storage.local` に保存する（sync は 1 項目 8KB の上限があるため）。設定値は `chrome.storage.sync`。
- **Q40「列の並べ替え」**: 列を左へ / 右へ 1 つ移動する操作。行のソートではない。
- **Q40 編集と入力欄の関係**: プレビュー上の編集（セル編集・列削除・列移動・転置）は内部の表モデルに対して行い、出力に即時反映する。入力欄のテキストは書き換えない。入力欄を編集・貼り付けし直すと表モデルは入力から作り直す（編集は破棄される）。
  - 入力から表モデルを作り直す（編集を破棄する）のは、入力の解釈が変わるときだけ: 入力欄の編集・貼り付け・クリア、入力形式の手動変更（判定失敗時の候補選択を含む）、オプションページでの前処理設定の変更。
  - 出力側の設定変更（出力形式・線種・行間罫線・曖昧幅・Markdown 整形・CSV 区切り・HTML スタイル・JSON 構造 / number・ヘッダーのチェックボックス）は、表モデルを保ったまま出力とプレビューを描き直す。オプションページで出力系の既定値が変わったときも同じ。
- **Q50**: プレビューを省略するしきい値は 5,000 セル（行数 × 列数）。省略した旨を表示し、変換とコピーは行う。
- **Q51**: 変換 UI 内 = 入力形式（自動 / 手動）・出力形式・ヘッダー有無・その出力形式に固有の主要な切替。オプションページ = すべての設定の既定値（線種・行間罫線・曖昧幅・Markdown 整形・CSV 区切り・HTML スタイル・JSON 構造・JSON 数値型・前処理の ON/OFF）。
- **Q5 / Q6**: 対応形式は 7 形式のみ。Jira・reStructuredText・LaTeX 等は実装しない。

## 3. 実装者判断（仕様の空白を最小の解釈で埋めた箇所）

| # | 対象 | 判断 |
|---|---|---|
| 1 | Q15 の初回既定値 | 出力形式の初期値は Markdown |
| 2 | Q51 変換タブ内の切替の保存 | 変換タブで変えた形式固有の切替（線種・桁揃えなど）はそのタブ限りで保存しない。保存するのは出力形式（Q15）だけ。オプションページで既定値が変わると、開いている変換タブにも変わった項目だけ反映する |
| 3 | Q7 手動の入力形式 | 手動で選んだ入力形式は保存しない（開き直すと「自動判定」） |
| 4 | Q28 手動上書きの持続 | ヘッダーのチェックボックスで上書きした状態は、入力欄を編集すると自動判定に戻る |
| 5 | Q28 自動判定の基準 | 形式の構造を優先する（Markdown の区切り行、HTML の thead / 1 行目が全て th、罫線表で内側の横罫線がヘッダー下の 1 本だけ、またはヘッダー下の罫線だけ線種が違う（`╞═╪═╡` / `+===+` など）、JSON のオブジェクト配列）。構造に手がかりが無い場合（TSV・CSV・全ての行間罫線が同じ線種の罫線表・内側の罫線が無い罫線表・2 次元配列 JSON・th の無い HTML）は、2 行以上あり 1 行目の全セルが空でも数値らしくもなければヘッダーとみなす |
| 6 | Q26 揃え指定の優先 | 入力に揃え指定が 1 列でもあれば（Markdown の `:`、HTML の `align` / `text-align`）、その表では全列で入力の揃えを使い、数値の自動検出はしない。列の転置をすると揃え指定は破棄して自動検出に戻す |
| 7 | Q19 ヘッダー部分の折り返し | ヘッダー下にだけ罫線がある表（C の扱い）でも、ヘッダー部分に複数の物理行があれば 1 つのヘッダーに改行で結合する。内側の横罫線が 2 本以上なら A、1 本なら C、0 本なら 1 物理行 = 1 行（ヘッダーは内容から推定） |
| 8 | Q30 JSON のセル内改行 | JSON も「その他」に含め、セル内改行を半角スペースにする |
| 9 | Q25 桁揃え時のヘッダー | 桁揃えした Markdown・罫線表・ASCII 罫線表では、ヘッダー行は左詰めにし、データ行だけ列の揃えに従う（Q25 の例 `| 四半期 | 売上   |` に合わせる） |
| 10 | Q23 曖昧幅 2 と罫線文字 | 罫線文字（─ │ など）自体が曖昧幅のため、曖昧幅 2 のときは罫線文字も幅 2 として扱い、列の内幅を 2 の倍数に切り上げて縦線の位置を揃える |
| 11 | Q29 / Q33 Markdown の空セル | 空セルは `| |`（空白 1 個）で出力する（Q29 の例 `| | | |` に合わせる）。区切り行は整形なしのとき `---`（揃えに応じて `:---` / `---:` / `:---:`）。セル内のタブは半角スペースにする |
| 12 | Q38 ヘッダーなしの表のオブジェクト配列 | キーを「列1, 列2, …」にする。ヘッダーの空セルは「列N」、重複キーは「名前_2」のように補う |
| 13 | Q39 number に変換する範囲 | `-?` ＋ 整数（先頭ゼロ不可）＋ 任意の小数部のみ。`+`・桁区切り・`%`・先頭ゼロ（`007`）は文字列のまま |
| 14 | Q5 JSON 入力の構造 | オブジェクト配列（キーの和集合を出現順にヘッダー化）・2 次元配列・プリミティブ値の配列（1 列）に対応。先頭が `[` / `{` で JSON として読めるが表の構造でない入力（単一オブジェクト、混在配列）は JSON と判定したうえで、その理由をエラーとして表示する。オブジェクト・配列のセル値は JSON 文字列にする |
| 15 | Q5 CSV 入力の区切り文字 | `,` `;` `|` のうち、行ごとの列数が最も揃い 2 列以上になるものを自動で選ぶ |
| 16 | Q5 HTML 入力 | 先頭がタグで、`<table>`・`</table>`・`<td>` / `<th>` がそろう入力だけを HTML と判定する（セル内の「`<table>`」という文字列では判定しない）。最初の `<table>` だけを読み、解析結果が 0 列なら失敗にする。`<br>` とブロック要素（p・div・li 等）の区切りをセル内改行にし、それ以外の空白は 1 個に詰める。script・style・template・noscript の中身はセルに入れない。セル内に入れ子の table があれば、そのセルのテキストを半角スペースでつなぐ |
| 17 | Q9 前処理の範囲 | 先頭の BOM（U+FEFF）の除去と改行コードの統一は設定によらず常に行う。共通インデントで除去するのは半角空白のみ。タブは TSV の空セルでありうるため残す。適用順は BOM → ANSI → コードフェンス → 表部分の抽出 → 共通インデント |
| 18 | Q9 表部分の抽出 | 入力を空行でブロックに分ける（引用符の内側の空行では分けない）。罫線表・Markdown は構造で表の範囲が確定するので、ブロックの前後から形式に合わない行（説明文）を空行が無くても切り落とす。CSV / TSV はブロックの行を削らない（列数の違う行は Q10 どおり空セルで補って警告する）。選ぶ順は 入力全体が JSON / HTML → 罫線表・Markdown → `<table` で始まる行から `</table>` まで → `[` で始まる行から `]` で終わる行まで（JSON） → CSV / TSV のブロック。同じ順位なら行数の多いもの。抽出で行を除外したときは、除外した行数を画面に通知する |
| 19 | Q8 候補の範囲 | 解析して 1 列以上の表になった形式を候補にし、2 列以上になった形式を先に並べる |
| 20 | Q36 リッチコピーの text/plain | リッチコピーは text/html と text/plain の両方に HTML ソースを入れる |
| 21 | Q47 保存のタイミング | 入力の変更から 300ms 後に保存する（連続入力でまとめる）。`pagehide` では即時保存（実装者判断 28） |
| 22 | Q18 リンクの URL | 許可リスト方式。C0/C1 制御文字と空白を除いてから判定し、http: / https: / mailto: / `#` で始まるもの / スキームの無い相対パス（`//` や `\` を含むものは除く）だけを `<a>` にする。URL 内の対応の取れた括弧（`Foo_(bar)`）は URL に含める |
